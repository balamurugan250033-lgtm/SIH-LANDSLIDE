NER Landslide Early Warning System

Smart India Hackathon 2026 — Project Report

Government of India · National Disaster Management Authority

1. Executive Summary

The NER Landslide Early Warning System is a comprehensive, multi-platform disaster management solution designed for the North-Eastern Region (NER) of India. It integrates real-time ML-based risk assessment, citizen reporting, official alert dispatch, offline-first mobile capabilities, and peer-to-peer mesh alert relay to ensure timely warnings even when internet connectivity is unavailable.

The system comprises three main interfaces: a Citizen Web Portal, an Admin Web Dashboard, and a Citizen Mobile App, all backed by a unified FastAPI backend with SQLite persistence.

Key Highlights

  • 4-Tier Risk Classification: Low, Moderate, High, Severe with distinct visual coding
  • Offline-First Mobile: Local SQLite cache, queued reports, auto-sync on reconnect
  • Mesh Alert Relay: Bluetooth/WiFi peer-to-peer alert propagation using Google Nearby Connections API
  • Real-Time GIS Mapping: Leaflet-based web map + native Android maps with risk-colored markers
  • Admin Alert Dispatch: Create, preview, and broadcast warnings across web, SMS, and push channels
  • Road & Connectivity Status: Live corridor status with alternative route recommendations

2.2 Data Flow

  1. Data Ingestion: Simulated sensor feeds (rainfall, soil moisture, slope angle) feed into the backend every 60 seconds
  2. ML Inference: Random Forest classifier computes landslide probability score
  3. Decision Engine: Maps probability to 4-tier risk level with explainable reasoning
  4. Alert Dispatch: Admin triggers notifications via web/SMS/push; alerts persist in database
  5. Citizen Consumption: Web portals and mobile app poll REST API for live risk status
  6. Mesh Relay: When offline, phones broadcast cached alerts via Nearby Connections; unseen messages are cached, displayed with “Received via mesh” tag, and rebroadcast with decrementing TTL
  7. Backend Re-ingestion: Phones with internet POST mesh-captured alerts back to backend for normalization

6. Mesh Networking

6.1 Protocol

The mobile app implements an offline emergency-alert relay using Google Nearby Connections API. Message format:

FieldTypeDescription
zone_codeStringAffected region name
risk_tierStringLOW / MODERATE / HIGH / CRITICAL / SEVERE
timestampStringISO 8601 alert timestamp
ttlIntegerHop count, starts at 5, decremented per relay
msg_idStringUnique message ID for deduplication
short_textStringBrief warning description

6.2 Behavior

  • Each phone maintains a local seen-cache of msg_id to avoid rebroadcast loops
  • When offline, phone periodically broadcasts cached alert set via Nearby Connections discovery/advertising
  • Nearby phones pick up new unseen messages, cache them, display with “Received via mesh” tag
  • If ttl > 0, the message is rebroadcast with decremented TTL
  • When a phone with internet receives a mesh message, it POSTs to the backend to re-enter the normal alert pipeline
  • Alert list UI updates live via React Native state listener — no manual refresh needed

6.3 Native Implementation

The mesh relay is implemented as a bare Android native module:

  • Kotlin Module: NearbyConnectionsModule.kt wraps Google Nearby Connections with @ReactMethod annotations
  • JS Bridge: mesh.js provides startAdvertising(), startDiscovery(), sendMessage(), and event listeners via DeviceEventEmitter
  • Package Registration: NearbyConnectionsPackage.kt registers the module with React Native

7. Admin Features

7.1 Alert Dispatch Workflow

  1. Admin opens Regions & GIS tab
  2. Clicks Issue Alert for a specific region
  3. Selects risk tier, enters title and message
  4. Chooses language (English, Hindi, Assamese, Bengali, Manipuri, Khasi, Mizo, Nagamese)
  5. Selects channel: Web Portal, SMS, Push Notification, or All Channels
  6. Clicks Dispatch Alert — notification is created with status “sent”
  7. Citizens see the alert in their web portal, mobile notifications tab, or via mesh relay

7.2 Road Status Management

  • Admin can create/update road status for any region
  • Status options: Open / At-risk / Blocked
  • Can add reason and alternative route
  • Citizens see road status in both web and mobile apps

7.3 Live Monitoring

  • System health badge updates every 30 seconds
  • Risk summary cards show count of Severe/Critical/High/Moderate zones
  • Pending reports count per region links directly to Reports tab

10. Conclusion

The NER Landslide Early Warning System demonstrates a production-ready architecture for disaster early warning in low-connectivity environments. By combining cloud-based ML inference, real-time web dashboards, offline-first mobile apps, and peer-to-peer mesh networking, the system ensures that critical landslide warnings reach citizens and administrators even when traditional internet infrastructure fails.

The modular design allows independent scaling of the backend, web portals, and mobile application, while the native Android mesh module provides a robust foundation for offline alert propagation that can be extended to additional disaster scenarios.

Future Enhancements

  • Integration with real IoT sensor networks and satellite data APIs
  • SMS gateway integration using Twilio for rural alert delivery
  • Multilingual voice alerts via IVR for low-literacy users
  • Drone-based post-disaster assessment integration
  • Community volunteer coordination module
  • Predictive evacuation route optimization using graph algorithms
